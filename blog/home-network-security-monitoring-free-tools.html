Home Network Security Monitoring: Free Tools That Actually Work

The average home network has 15 to 30 connected devices. Smart TVs, thermostats, cameras, game consoles, phones, laptops, and a router that probably hasn't been patched in two years. And most people have zero visibility into what any of those devices are doing.

This guide covers the free tools that give you real monitoring — not just a device list, but actual alerts when something suspicious happens.

The problem you probably don't know you have: Compromised IoT devices are used as botnets for months or years before the owner notices. Your smart bulb or printer could be participating in DDoS attacks right now. You'd never know without monitoring.

Step 1: Know What's on Your Network

You can't monitor what you can't see. Start with a device inventory.

# nmap — find all active devices on your local subnet
sudo nmap -sn 192.168.1.0/24

# Or with MAC address and vendor lookup:
sudo nmap -sn -PE --send-ip 192.168.1.0/24

# Output shows: IP, MAC, vendor (inferred from MAC OUI)
# Look for anything you don't recognize

Most home routers also show connected devices in their admin panel (usually at 192.168.1.1 or 192.168.0.1). Cross-reference: if a device shows up in nmap but not your router's list, something is wrong.

Step 2: Watch for New Devices Joining

arpwatch emails you every time a new device appears on your network or an existing device's MAC address changes (which could mean ARP spoofing).

sudo apt install arpwatch
sudo systemctl enable arpwatch
sudo systemctl start arpwatch

# Edit /etc/arpwatch.conf to set your email address
# New device → email alert within seconds

This runs silently in the background. The only time you hear from it is when something new shows up or a device behaves strangely.

Step 3: Monitor Your Router for Open Ports

Many home routers expose administrative interfaces to the internet by mistake. Check yours:

# Check if your router has management ports open externally
# First, find your public IP
curl -s ifconfig.me

# Then scan from a different network or use Shodan:
# shodan.io/host/

# Common dangerous open ports on routers:
# 23 (Telnet), 80/443 (web admin), 7547 (TR-069 ISP management)
# 8080/8443 (alternate HTTP admin), 1900 (UPnP)
Port 7547 is particularly dangerous. TR-069 is the protocol ISPs use to remotely manage your router. If it's exposed to the internet (not just your ISP), attackers can exploit it to take full control of your router — this was the vector for the Mirai botnet's router attack wave.

Step 4: DNS Leak Testing

Your DNS queries reveal every domain you visit. If your DNS is leaking through your ISP instead of your configured resolver, you lose both privacy and the blocking benefits of tools like Pi-hole.

# Check which DNS servers you're actually using
cat /etc/resolv.conf

# Run a leak test from the terminal
nslookup myip.opendns.com resolver1.opendns.com

# Or visit dnsleaktest.com for a browser-based test

If the DNS servers shown are not the ones you configured, your VPN is leaking or your router is overriding your settings.

Step 5: Firewall Audit

Most Linux systems ship with a firewall that's either misconfigured or disabled. Check yours:

# Check ufw status
sudo ufw status verbose

# If inactive, enable with sane defaults:
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh   # only if you need SSH
sudo ufw enable

# Check iptables directly
sudo iptables -L -n --line-numbers
